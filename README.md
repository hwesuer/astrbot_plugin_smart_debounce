# astrbot_plugin_smart_debounce

AstrBot v4.23.6+ 智能消息防抖动插件。

> ⚠️ **重要提醒：每次判断均需调用 LLM API**
>
> 本插件每拦截一条用户消息，就会调用一次你配置的 LLM API 来判断消息是否说完。
> 每次判断大约消耗 **150~200 token**。
>
> 如果你使用的是 DeepSeek 这类平价 API，一天重度使用下来 token 费用也基本可以忽略。
> 但如果用的是较贵的模型（如 GPT-4），请注意控制用量。
> 建议使用版本大于等于4.23.6的astrbot，因为之前的版本并没有进行测试，可能会有未知的错误
>  -如果有bug或建议，欢迎提交issue⭐

## 功能

当用户连续发送多条短消息（例如分多条发送一段完整的话）时，本插件会：

1. **拦截消息** — 在 `on_llm_request` 阶段（优先级 80）拦截用户消息。
2. **缓冲累积** — 将消息暂存到缓冲区，按 `session_id` 区分不同会话。
3. **LLM 完整性判断** — 调用配置的 LLM API，判断当前累积的消息是否已经完整表达了一个意思。
4. **合并放行** — 判断为完整后，将缓冲区中的消息合并为一个 `req.prompt`，放行给 AstrBot 处理。
5. **超时兜底** — 若用户停止发送，超过配置的 `timeout_seconds` 后自动将缓冲的消息合并发送。

## 配置项

| 配置项 | 类型 | 默认值 | 说明 |
|--------|------|--------|------|
| `enabled` | bool | `true` | 是否启用插件 |
| `api_base` | string | `""` | 判断消息完整性的 LLM API 地址，兼容 OpenAI 接口格式（如 `https://api.deepseek.com`） |
| `api_key` | string | `""` | API 访问密钥 |
| `model` | string | `""` | 使用的模型名称（如 `deepseek-chat`、`gpt-3.5-turbo`） |
| `timeout_seconds` | int | `20` | 超时时间（秒），用户停止发送后等待该时间自动发送缓冲消息 |
| `prompt_template` | text | 见下方 | 判断消息完整性的提示词模板，使用 `{messages}` 作为占位符 |

默认 `prompt_template`：

```
你是一个判断用户是否把话说完的助手。
以下是用户连续发送的消息片段，请判断用户是否已经完整表达了他的意思。
考虑以下情况：
- 结尾有句号、问号、感叹号等结束标点 -> 可能说完了
- 以「然后」「但是」「不过」「还有」等词结尾 -> 可能没说完
- 只说了一个词或短语 -> 可能没说完
- 明显是一句话的中间部分 -> 没说完
- 一句话结构完整、意思清晰 -> 说完了

仅返回JSON格式，不要包含其他内容：
{"is_complete": true} 或 {"is_complete": false}

用户消息片段：
{messages}
```

## 工作流程

```
用户发送消息 → on_llm_request(priority=80)
     ↓
缓冲区追加消息
     ↓
调用 LLM 判断完整性
   ↙         ↘
完整          不完整
 ↓              ↓
合并消息       stop_event()
修改req.prompt  启动超时任务
放行处理        等待新消息或超时
```

## 依赖

- `httpx >= 0.24.0`

## 注意事项

- 若未配置 API 地址、密钥或模型，插件将直接放行所有消息，不做拦截。
- LLM API 调用失败时，默认视为消息已完整，放行处理，防止消息被阻塞。
- 建议使用低延迟模型来做完整性判断，以减少用户感知的等待时间。
- 插件卸载时会自动把缓冲区中积压的消息发送出去，不会丢失用户说到一半的内容。
